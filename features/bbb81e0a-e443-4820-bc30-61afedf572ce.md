## 2. Root cause & decisions

# Decision: P0 messages never auto-expire (task bbb81e0a)

ROOT_CAUSE: The relay had a single TTL policy for every priority — any message
whose `ttl_seconds > 0` window elapsed was stamped `expired_at` by `ExpireMessages`
and hidden by the inbox read predicates. A P0 (critical interrupt) with a finite
caller ttl therefore silently dropped out of the inbox once its window passed. T6
added a durable deadletter journal (a queryable floor so an expired P0 isn't gone
forever) but nobody reads the deadletter table proactively — the live inbox is
where a P0 must stay. CTO T6 policy: P0 must NEVER auto-expire regardless of caller
ttl; it stays surfaced until acknowledged.

## Decision
Enforce the policy at three points (belt-and-suspenders — a P0 survives regardless
of how it entered the DB):

1. **Insert-side (`normalizeTTL`, messages.go):** P0 -> `ttl_seconds = 0`
   REGARDLESS of the caller's ttl. P1 -> 7d (604800) default when the caller leaves
   ttl unspecified (`<0`); explicit P1 ttl respected. P2/P3 keep the 4h (14400)
   default. Applied in both `InsertMessage` and `InsertMessageWithDeliveries` so no
   send path can store a finite-ttl P0.

2. **Sweep-side (`ExpireMessages`):** add `AND priority != 'P0'` so even a legacy row
   or a direct-insert path with a P0 at `ttl>0` is never stamped `expired_at`.
   `priority` is `TEXT NOT NULL DEFAULT 'P2'` (db.go:397) so `!= 'P0'` has no
   NULL tri-state hole.

3. **Read-side (4 inbox predicates: deliveries.go x2, messages.go x2):** add
   `OR m.priority = 'P0'` so any P0 stays surfaced even if a legacy row's ttl window
   already elapsed before this policy shipped.

Additive, no schema change, backward-compatible (older fleet DBs + older agents
keep working). Deliveries non-destructive-peek invariant untouched.

## Rejected alternatives
- **Insert-normalization only (no sweep/read guard):** leaves already-stored legacy
  P0 rows (finite ttl) still hidden/expirable. Rejected — policy must be robust to
  existing data, not just new sends.
- **A migration to reset existing P0 `ttl_seconds=0`:** would touch schema/migration
  (wraith-backend's lane) and still not cover future direct-insert paths. The
  read-predicate + sweep guard cover legacy rows with zero migration.
- **Change the deadletter to be actively surfaced instead:** doesn't satisfy "stays
  in the LIVE inbox"; deadletter remains the durable floor (T6), not the fix.
