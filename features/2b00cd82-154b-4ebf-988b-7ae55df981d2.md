## 2. Root cause & decisions

# comms-discipline S3 — typed status (send_status)

ROOT_CAUSE: Comms-discipline mechanism (B) from DEC-relay-comms-discipline-1 was unbuilt.
Agents had only free-form messages for status updates; a status either woke the recipient
(noise) or hid its structure. There was no typed, no-wake channel for "here's my done/doing/
blockers" — the structural half of the discipline (S1 shipped the action_required tag; S4
shipped the metric; S3 is the typed-status producer).

## Decision
Add a dedicated `send_status` MCP tool (messaging category):
- Slots: `done[]`, `doing[]`, `blockers[]` + one capped free-text `note`, stored in the
  message metadata as `{status_schema:1, done, doing, blockers, note, truncated?}`.
- **Accept-and-slot, never reject**: over-cap item counts / over-long items / over-long note
  are truncated and recorded under `truncated`; the send never fails on shape.
- **Always no-wake**: message type `status`, `action_required` forced `none`. A listed blocker
  is SURFACED in the inbox, not a wake (Ruling-3: passively listing a blocker is not
  escalating). To escalate, send a question — this path never touches question/blocker MESSAGES,
  honoring the decision's GUARD (never cap/gate a question or a blocker message).
- **P0 escape hatch**: a P0 status still wakes via the guard-first predicate's P0 clause.
- Human-readable body is rendered too, so get_inbox shows the status without a metadata parse.

## Key choices / rejected alternatives
- **Dedicated tool vs a `status` param on send_message**: chose a dedicated tool — clearer for
  agents to discover, keeps the no-wake+accept-and-slot semantics self-contained, and avoids
  branching send_message's already-large handler.
- **Recipients**: direct agent / '*' / conversation (reuses db.ResolveRecipients). `team:` is
  explicitly rejected with a helpful error (v1 scope; a status goes to a lead or the fleet).
- **No schema change / no new writer**: reuses InsertMessageWithDeliveries + the existing
  metadata column. Single-writer + non-destructive inbox untouched.

## SCOPE NOTE — budget-driven description trims (behavior-neutral)
Adding a 73rd tool pushed the tool-schema budget (TestToolSchemaBudget, 55296-byte ceiling)
over. To fit, I shortened the DESCRIPTION STRINGS ONLY (no behavior, no param, no name change)
of: register_agent, reclaim_task, is_eligible, link_pr, reconcile_pr, set_run — plus kept
send_status's own descriptions terse. All load-bearing facts preserved. Flagged here so the
reviewer sees the cross-tool doc churn is intentional, not scope creep.
