## 2. Root cause & decisions

# steal #9 follow-up — signal webhook: no-lost-signal + quota gate

ROOT_CAUSE: The review of steal #9 (merged 6b4140c1) flagged two real, non-blocking gaps in
the signal webhook:
1. **record-then-act loss** (`webhook_signal.go:114`): InsertEvent (the dedup row) committed
   BEFORE dispatchCore. A transient dispatch failure returned 500 while the delivery id was
   already consumed, so an at-least-once redelivery deduped to 200 and the ticket was never
   created — the signal silently lost.
2. **quota bypass** (`webhook_signal.go:137`): the signal path called dispatchCore directly,
   skipping the CheckQuotaError the MCP dispatch path enforces — a signed source could flood
   the board past the project task quota.

## Decision
- **Quota gate BEFORE reservation**: check `CheckQuotaError(project, "signal:"+source, "tasks")`
  before InsertEvent; over quota → 429. Checked pre-reservation so a rejected signal leaves no
  dedup row and is retryable after the window resets.
- **Compensating delete on dispatch failure**: treat InsertEvent as a *reservation*; if
  dispatchCore errors, `DeleteEventByDelivery(project, deliveryID)` releases it so a redelivery
  re-attempts instead of deduping to a no-op. Net: no lost signal AND still no duplicate ticket.
- New DB helper `DeleteEventByDelivery(project, delivery_id)` — best-effort, project-scoped.
