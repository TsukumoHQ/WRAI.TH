# Decision — task b092a6be: close the typed-ticket enforcement loophole (every native path)

ROOT_CAUSE: The typed-ticket guard (refuse a dispatch missing goal/acceptance_criteria/dod
on a `require_typed_ticket` project) was implemented PER-HANDLER — duplicated in
`HandleDispatchTask`, `HandleBatchDispatchTasks`, and `apiDispatchTask`. But two native
creation paths — cron scheduled dispatch (`cron.go`) and the inbound-signal webhook
(`webhook_signal.go`, which self-dispatches a followup with a bare `db.TypedTicket{}`) —
reach the DB insert via `dispatchCore` → `db.DispatchTask` WITHOUT passing any of those
handlers. So a bare, untyped ticket slipped through on an enforced project. Founder proof:
task 43189533 (backend-lead self-dispatched a review-followup) traversed all the way to the
QA gate rendering `Acceptance Criteria: (untyped ticket — no acceptance criteria)`.

## Decision
Move enforcement to the SINGLE creation choke: `db.DispatchTask` (the only `INSERT INTO
tasks` path for native tasks — every caller funnels through it). Enforcement lives on the
data layer, gated per project, so no path can drift or bypass it.

- Add `db.TypedTicket.Missing()` (+ `hasAcceptanceItems`) as the single source of truth for
  "what makes a ticket bare" (empty / non-array / all-blank acceptance_criteria = absent),
  and a typed `db.TypedTicketError{Project, Missing}`.
- `db.DispatchTask` refuses when `d.ProjectRequiresTypedTicket(project)` and `ticket.Missing()`
  is non-empty, checked on the RAW ticket before any write/side-effect. Enforcement is
  identity-agnostic (checks project + ticket only) — no agent-origin/self-dispatch bypass.
- Delete the three duplicated relay helpers (`missingTicketFields` / `hasAcceptanceItems` /
  `ticketRefusal`) and the per-handler pre-checks; handlers now only translate a
  `*db.TypedTicketError` into their response shape (MCP tool error / per-item batch error /
  HTTP 400).
- Signal webhook: a typed-ticket refusal is PERMANENT, so the handler must NOT release the
  delivery-id for at-least-once redelivery (that would poison-loop). Return 422 and keep the
  marker (redelivery dedupes); transient errors keep the existing release + 500 retry.

## Paths audited (every `INSERT INTO tasks`, whole repo)
- `tasks.go:196` = `DispatchTask` → GUARDED. Covers: dispatch_task tool, batch_dispatch_tasks
  (per-item), apiDispatchTask (HTTP), cron, inbound-signal/self-dispatch followup.
- `tasks.go:1048` `UpsertLinearTask` + `linear.go:137` = `source='linear'` mirror replica,
  NOT native. Enforced separately at the Linear connector (`handleTypedTicket` writes a
  refused-mirror row for non-conforming issues).

## Rejected alternatives
- Guard in `dispatchCore` instead of `db.DispatchTask`: rejected — batch and api call
  `db.DispatchTask` directly, bypassing `dispatchCore`. Only the DB layer is the true choke.
- Add enforcement to `UpsertLinearTask`: rejected — refused-mirror rows carry no typed fields
  by design; guarding there breaks the Linear refused-mirror feature. Linear has its own guard.
- Keep the per-handler pre-checks as well as the DB guard: rejected — that is the exact
  per-path duplication that drifted and caused this bug.
