## 2. Root cause & decisions

# Decision: filter conversations/inbox list by user (ticket/e2f5ad14 #1)

ROOT_CAUSE: The web list endpoints `GET /conversations` and `GET /messages` had no
way to scope results to a single agent/user — every caller got the whole
project's conversations and the 500 most-recent messages, with no server-side
filter. To view one user's activity the client had to pull everything and filter
in the browser, which both wastes bytes and silently drops a quiet user's older
messages once the 500-row window fills with a busy user's traffic.

## Decision
Add an additive `?user=<name>` query param to both list endpoints.
- `GET /conversations?user=X` → only conversations X is an ACTIVE member of
  (`conversation_members … left_at IS NULL`).
- `GET /messages?user=X` → only messages where X is sender OR recipient.
- Filter is case-insensitive (`LOWER(col)=LOWER(?)`), matching how member names
  are stored (lower-cased) and tolerating any casing drift in `from/to_agent`.
- Empty/absent `user` preserves the exact legacy behavior — the original DB
  methods now delegate to the new `…ForUser` variants with an empty user, so no
  caller signature changed and no test churned.

## Why this shape
- **Filter in SQL, before LIMIT** (not in the handler over an already-capped
  slice): a busy project must not starve a quiet user out of the 500-row window.
- **New `…ForUser` methods, originals delegate** (vs. adding a param to the
  existing signatures): additive, zero churn across the 5 existing test call
  sites, backward-compatible.
- Read-only; no schema change, no writer, no migration, uses the RO pool.

## Rejected alternatives
- Client-side filtering: loses bytes + drops quiet users past the row cap.
- Changing the existing DB method signatures to take `user`: breaks 5 test
  callers and every future caller for no gain.
- Filtering the `/all` cross-project + `/inbox/unread-count` aggregate endpoints:
  scope creep — those are admin/aggregate views, not the per-project list the
  ticket names. Deferred; easy to add later with the same pattern if asked.

## Scope
`internal/db/web_queries.go` (2 additive methods + delegation),
`internal/relay/api.go` (2 handlers read the param),
`internal/db/web_queries_filter_test.go` (new). No cross-lane / shared-file edits.
