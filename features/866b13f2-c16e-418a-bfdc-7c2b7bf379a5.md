# Decision — tasks.verify_cmd, relay half of DEC-niwa-goal-validate-1 (task 866b13f2)

ROOT_CAUSE: founder ruled cc80c367 (DEC-niwa-goal-validate-1) that gate
reviewers get the ticket's GOAL plus a daemon-run VALIDATE command
(verify_cmd) to machine-check a ticket before folding a verdict. The agentd
halves were already cut (ef4a439c backend-lead, c0ee8b5b gate-lead); the
relay never had a place to store or serve that command, so the feature had
no data path — this task is that relay half, spec'd by niwa-cto (msg
e99c3651): an additive nullable `tasks.verify_cmd TEXT` column, threaded
through the SAME dispatch/update/read plumbing as the existing typed-ticket
fields (goal/acceptance_criteria/dod), but never enforced.

Decision: add `verify_cmd` in lockstep with `taskColumns`/`scanTask` (Go's
column-count/scan-order invariant — the same lockstep the wraith-dev skill
flags as a real historical bug class), give `TypedTicket` a `VerifyCmd
*string` field that is DELIBERATELY excluded from `Missing()` so its absence
can never trigger a `TypedTicketError` on any project, enforced or not.
Threaded through:
- `dispatch_task` / `batch_dispatch_tasks` (MCP handlers) — accept it,
  pass-through via the existing `db.TypedTicket` plumbing (no new function
  signature needed on `dispatchCore`/`DispatchTask` beyond the struct field).
- `update_task` — added as a 10th `*string` param to `UpdateTaskFields`,
  folded into the SAME `contractChanged`/audit-snapshot logic and the SAME
  dispatcher-only permission gate goal/acceptance_criteria/dod already use
  (spec: "audited exactly like goal/acceptance_criteria/dod").
- `get_task` / `list_tasks` — automatic via `models.Task`'s
  `verify_cmd,omitempty` json tag, no handler change.
- `get_session_context` task previews — NOT automatic (TaskSummary is a
  separate hand-projected struct, `internal/relay/project.go`, that doesn't
  carry goal/AC/dod at all today); added `VerifyCmd` to `TaskSummary` +
  `summarizeTask` + `taskSummaryBytes`' budget estimate specifically because
  this task's own acceptance criteria names get_session_context explicitly,
  unlike the other three fields which happen not to be there.
- Migration: `ensureColumns(conn, "tasks", {"verify_cmd": "TEXT"})` — same
  additive/idempotent mechanism every other tasks-table column already uses
  (`PRAGMA table_info` check before `ALTER TABLE`), auto-runs on startup,
  nullable (not `NOT NULL DEFAULT ''` like goal/dod — the spec explicitly
  calls it nullable, and its absence is the common, expected, unenforced
  case, unlike goal/dod which an enforced project can require).

No relay-side validation of the command string: it round-trips through a
parameterized SQL string exactly as given (proven by a test with shell
metacharacters in it) — agentd owns validating and running it.

Alternatives considered:
- A separate `verify_cmd`-only DB method instead of extending `TypedTicket`.
  Rejected: `TypedTicket` already flows unmodified through `dispatchCore` →
  `DispatchTask`'s INSERT; adding the field there means dispatch_task and
  batch_dispatch_tasks need zero signature changes downstream of the handler,
  only the struct gains a field — smaller diff, one less thing to keep in
  sync.
- Also retrofitting goal/acceptance_criteria/dod onto `TaskSummary` while
  touching that struct anyway. Rejected: out of scope for this task — the
  task asks for verify_cmd in three specific places, not for closing an
  unrelated pre-existing gap in the other three fields' session_context
  coverage. Left as-is.
