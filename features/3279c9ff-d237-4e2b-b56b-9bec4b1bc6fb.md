# Decision — P3 purge dead review-* reviewers + standing TTL reaper (task 3279c9ff)

ROOT_CAUSE: the niwa gate registers an ephemeral `review-<taskid>` agent per
review and never tears it down (DEC-niwa-reviewer-lifecycle-1), so the relay
registry (= the agents table) accumulated ~385 inactive review-* rows across 10
projects on synx-prod — a founder-visible roster mess. The relay had no reaper
for them and no server-side way to clear the backlog without a raw external
SQL write (a second writer on the single-writer DB) or a daemon relaunch (frozen).

DECISION — a server-side purge run by the RUNNING relay (its own writer
connection = single-writer-safe; an external UPDATE would both risk corruption
and not be reflected in the relay's own view), in two parts sharing one primitive.

1. db.PurgeStaleReviewers(dryRun, olderThan) — the shared, in-process primitive.
   Matches inactive review-* NOT holding a live (accepted/in-progress/in-review)
   task via one predicate reused by the candidate SELECT and the mutating UPDATE
   (skip-live re-checked at mutation time, closing the TOCTOU window).
   SOFT-delete only (status='deleted', row kept, deactivated_at preserved =
   recoverable, never a hard row delete). Idempotent (a re-run finds nothing —
   the rows are no longer 'inactive'). olderThan==0 = every inactive reviewer
   (one-shot backlog); olderThan>0 = only those inactive past the window (reaper).

2. ONE-SHOT admin endpoint: POST /api/admin/purge-reviewers, DEFAULT dry-run —
   it logs the candidate count and mutates nothing unless ?dry_run=false. Gated
   by the existing /api middleware (RELAY_API_KEY / loopback), exactly like the
   sibling admin write routes (DELETE /projects, PUT /settings) in ServeAPI.
   Server-side execution = single-writer-safe + the roster (read from the DB)
   reflects the change immediately.

3. STANDING TTL reaper: on the existing StartCleanup maintenance tick, call
   PurgeStaleReviewers(false, reviewerTTL) with the same skip-live guard.
   reviewerTTL = DefaultReviewerTTL (7d), config via RELAY_REVIEWER_TTL_DAYS.
   Backstop so the backlog never re-accumulates. No new goroutine.

SKIP-LIVE is HARD: an 'active' reviewer is never matched (only status='inactive'),
and any reviewer still holding a live task is excluded by the NOT EXISTS guard —
tested (an in-review task blocks the purge; a done task does not).

REGISTRY NOTE: the SessionRegistry (notify.go) tracks only live SSE/MCP session
IDs; an inactive reviewer has none, so there is nothing to unregister. The roster
the founder sees is DB-backed, so the soft-delete alone clears it — the reason
this must run in-process is the single-writer invariant, not a session cache.

REJECTED — external CLI raw-SQL purge: a second writer on the single-writer DB
(corruption risk) and invisible to the running relay until restart (frozen). The
in-process endpoint + reaper are the correct surface.

REJECTED — hard row-delete: irreversible; the ticket + the Phase-0/1 discipline
require recoverable soft-delete (status='deleted', row retained).

REJECTED — a boot-time one-shot (migration-style): would only fire on relaunch,
which is frozen; the on-demand endpoint runs against the already-running relay.
