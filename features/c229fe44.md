## 2. Root cause & decisions

ROOT_CAUSE: HandleUpdateTask never parsed goal/acceptance_criteria/dod from the request, and UpdateTaskFields never accepted or wrote them — the typed-ticket contract fields were simply absent from the update path (not a deliberate immutability choice, an omission in the handler-to-DB mapping). A re-scope attempt silently no-opped on those three fields while title/description/priority/board_id updated normally.

DECISION: option (a) per cto — dispatcher-only write, audited, never silent-ignore.
- internal/db/tasks.go: UpdateTaskFields gained goal/acceptanceCriteria/dod *string params. When any is non-nil, the old values are snapshotted and appended to the existing generic audit_log via RecordAudit(action="contract_updated", details=JSON{old,new}) before the row is overwritten — reuses the audit infra already used for lease-transfer auditing and already exposed read-only via GET /api/audit?resource=<task_id>, instead of a bespoke history table.
- internal/relay/handlers_tasks.go HandleUpdateTask: parses the three fields; if any are set, refuses with a Forbidden permission error when the calling agent != task.DispatchedBy (assignee can't rewrite their own grading bar), and validates acceptance_criteria as a JSON array before writing.
- internal/relay/tools.go updateTaskTool(): added the three params to the schema (trimmed descriptions to stay inside TestToolSchemaBudget's 56320-byte cap).
- internal/relay/api.go apiUpdateTask (REST/web path): compile-fixed for the new UpdateTaskFields signature only — deliberately NOT wired to re-scope the contract from the web UI in this task (no dispatcher-identity concept over that path yet); flagged as a known gap, not silently dropped.

REJECTED ALTERNATIVE: option (b), explicit-refuse/immutable-contract. Not pursued — cto's stated preference was (a), and (a) still satisfies "never silent" while keeping the re-scope workflow useful.

Repro: internal/relay/update_task_contract_test.go — dispatcher re-scope updates fields + lands a contract_updated audit entry with old+new; assignee attempt on the same fields is refused (Forbidden, names "dispatcher") and leaves the contract byte-for-byte unchanged; a third test pins that title/description (non-contract fields) still work for the assignee.
