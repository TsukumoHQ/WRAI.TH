## 2. Root cause & decisions

# scheduled/cron typed-ticket creation (task 4cee49b6, niwa steal #8)

ROOT_CAUSE: Recurring fleet work (dep bumps, overnight triage, changelog draft, stale-PR sweep — the process-miner candidates) has to be hand-dispatched every time; there is no way to say "create this typed ticket on a schedule." Pure scheduling gap on top of the existing dispatch pipeline.

## Decision (additive, config-gated, inert by default)
- **`internal/relay/cron.go`** — a 6-field cron parser (`sec min hour dom month dow`, supporting `*`, `n`, `a-b`, `*/step`, `a-b/step`, comma lists, and standard dom/dow OR semantics) + a minute-granular scheduler goroutine.
- **Config source**: the `cron_schedules` setting (JSON array of `CronSchedule`). Absent/empty ⇒ the scheduler is a no-op, so the feature ships off until an operator populates it. No schema change (settings KV).
- **Pipeline reuse**: each fire calls the SAME `dispatchCore` used by `dispatch_task` (auto board/human-profile, profile-fanout inbox deliveries, `task.dispatched` event), so a scheduled ticket is indistinguishable from a hand-dispatched one. Tickets are typed (goal/acceptance_criteria/dod).
- **Idempotency (no dup tickets)**: at most once per matching minute per schedule. The dedup marker (`cron:lastfire:<id>` = the fired minute) is persisted in the settings KV and written BEFORE the dispatch, so a restart never re-fires an already-fired minute and a crash mid-fire cannot double-dispatch (at-most-once; a lost create surfaces as a missing ticket, preferable to a storm). The scheduler ticks every 30s and dedups by minute so no matching minute is skipped on drift.

## Notes / limitations
- Minute-granular: the scheduler evaluates the minute boundary, so the seconds field should be `0` or `*` (documented on parseCron). Honest for a ticket scheduler; no second-precision need.
- Single-writer safe: one relay process runs one scheduler goroutine; the GetSetting-check → SetSetting dedup has no concurrent writer to race.

## Rejected alternatives
- **A cron library (robfig/cron)** — none in go.mod; a 6-field parser is ~80 lines and avoids a new dependency on the fleet backbone.
- **A dedicated cron_schedules table** — settings KV already exists, is operator-editable at runtime like notification rules, and needs no migration.
