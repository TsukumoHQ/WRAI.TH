# cron dedup durable-marker fix (follow-up to 4cee49b6 / review notice)

ROOT_CAUSE: review-4cee49b6 (notice, non-blocking) flagged that the cron dedup marker is written via SetSetting, which swallows its write error (projects.go, no return). If that write silently fails, the same-minute guard (GetSetting == minuteKey) stays blind and the next 30s tick re-fires a DUPLICATE ticket — the at-most-once guarantee leaned on a fire-and-forget write.

## Decision
Gate the dispatch on a CONFIRMED-durable marker: after SetSetting, read it back; only dispatch if GetSetting == minuteKey. If the marker did not persist, skip this occurrence (log) rather than fire. Trade-off: a rare write failure now skips a fire (a missing ticket, self-corrects next occurrence) instead of emitting a duplicate — correct for a "no dup tickets" DoD. A confirmed marker guarantees the next tick's guard sees it. Self-contained in cron.go (my lane); no change to the shared SetSetting API.

## Rejected alternative
- Error-returning SetSetting — cleaner in theory but changes a shared settings API (projects.go, wraith-backend's zone) used by many callers; broader blast radius than the local read-back.
