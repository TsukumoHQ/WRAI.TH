## 2. Root cause & decisions

# Decision — b3d061a6: PR-reconcile sweep (pr_state-independent) + lease sweeper (G3/G4)

ROOT_CAUSE (two independent gaps making task convergence NOT self-healing):

G3 — Once a `pull_request` webhook (or the poll write-back) persists pr_state='merged'
(or 'closed') but the follow-on task transition is missed, the task strands: the only
reconcile candidate set, `db.ListPRReconcileCandidates` (tasks.go:211,218), filters
`pr_state='open'`. So a merged task is BOTH invisible to the external poller AND never
converges internally — it sits in-review forever. This is the 43189533-class "merged PR
strands in-review" failure the DOD calls out.

G4 — `internal/db/task_lease.go` had only `ReclaimTask` — an EXTERNAL, supervisor-driven
reclaim that names a specific new holder. There was NO internal, unattended sweeper, so a
dead reviewer/owner's expired lease left the task stuck with nothing to recover it inside
the relay.

## Decision
Two relay-INTERNAL periodic sweeps in one new `StartTaskMaintenanceSweeper` goroutine
(2-min tick, wired in main.go beside StartCleanup/StartCronScheduler, stops on shutdown):

- G3 `db.ListStrandedPRTasks` selects tasks with pr_state in ('merged','closed') that are
  still non-terminal (excludes already-settled closed→blocked). The relay loop converges
  each off the ALREADY-PERSISTED pr_state via the SAME `prTargetFromState` map +
  no-resurrect `ForcePRTransition` the webhook/poll paths use. No gh call — the relay stays
  INBOUND-ONLY (it never reaches GitHub; it acts only on state a webhook already delivered).
- G4 `db.SweepExpiredLeases` requeues to 'pending' every held task
  (accepted/in-progress/in-review) whose lease EXPIRED and whose holder is DEAD (not
  agentLive). A LIVE holder on an expired lease is LEFT ALONE (the 2h TTL is a dead-holder
  backstop, not a liveness probe — a heads-down agent never loses its task). The relay loop
  escalates each recovery via an event + a profile nudge so a live agent re-claims.

## Invariants held
- No-resurrect: both sweeps exclude terminal (done/cancelled); G4 only touches held states;
  G3 excludes settled closed→blocked; ForcePRTransition keeps its terminal guard.
- TOCTOU-free: each G4 requeue is a CAS UPDATE guarded on (id,project,lease_holder,status);
  a concurrent claim/heartbeat/transition wins (RowsAffected==0 → skip). ForcePRTransition
  is idempotent.
- Single-writer: SELECTs use the RO pool (d.ro()), the RO cursor is drained+closed before
  any writer UPDATE; writes go through the single writer. Periodic (2-min) maintenance, not
  a per-request hot-path write; empty when there's no drift (self-limiting).
- No schema change: pr_state + lease_* columns already exist. SweepExpiredLeases SELECTs
  explicit columns (not scanTask), so no agentColumns/taskColumns count coupling.

## Rejected alternatives
- Widen `ListPRReconcileCandidates` to non-open PRs instead of a new query: rejected — that
  is the EXTERNAL poller contract (open = "still needs watching"); overloading it would
  change what niwa sees. A dedicated stranded-set query + internal convergence keeps the
  poller contract intact and makes convergence work with NO poller (the goal).
- Auto-requeue a LIVE holder's expired-lease task: rejected — would yank tasks from
  heads-down agents; contradicts the generous-TTL design. Dead-holder-only is the safe line.
- Duplicate the pr_state→target map in the DB layer: rejected — reuse relay
  `prTargetFromState` so webhook, poll, and sweep apply ONE map (no drift).
