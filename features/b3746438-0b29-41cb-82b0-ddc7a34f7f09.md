## 2. Root cause & decisions

# niwa steal #11 — living ADR graph (causal, gate-checked, mermaid)

ROOT_CAUSE: The relay already stored decisions (memory layer="decision", with a supersede
chain), but they were scattered prose: no explicit causal `depends-on` links, no way to RENDER
the ledger, and no read the QA gate could hit to check "does this change contradict a live
decision?". Decisions were recorded but not queryable as a causal graph.

## Decision
Make the existing decision store CAUSAL + gate-checked + mermaid-rendered — all additive:

1. **Causal links** — `DecisionValue.depends_on []string` (additive JSON, omitempty). Set via a
   new optional `depends_on` param on the `remember` tool. `supersedes` already existed; together
   they are the two edge kinds. Refs are accept-and-store (an unknown/forward ref is kept and
   drawn as a stub node), so a decision can reference one not yet written.
2. **Mermaid emitter** — `DecisionGraphMermaid(project)` renders the full ledger (active +
   archived) as a GitHub-native `graph TD`: solid `-->|supersedes|` edges, dashed `-.->|depends|`
   edges, superseded nodes styled `archived` so the live frontier stands out. Deterministic
   (sorted), rune-safe labels, quote-escaped.
3. **Gate-check read** — `RelevantDecisions(project, area)` returns the LIVE decisions governing
   an area (exact or prefix match, so "relay/comms" hits "relay/comms-discipline"); empty area →
   all live. The gate fetches this for a change's area to check contradiction.

Both reads are exposed as REST (no MCP tool, no tool-schema-budget cost):
`GET /api/decisions/graph?project=` and `GET /api/decisions/relevant?project=&area=`. The niwa
QA gate (a daemon-side shell) curls these; keeping them off the MCP surface avoids the tight
73-tool schema budget.

## Rejected alternatives / trade-offs
- **MCP tools for graph + relevant** (vs REST): rejected — the tool-schema budget is at its
  ceiling and the consumer (the gate) is a shell, not an agent. REST fits and costs no budget.
- **A new causal-links table**: rejected — the links live in the decision's JSON value (additive,
  no migration, backward-compatible with older DBs).
- **Reject dangling depends_on refs**: rejected — a living graph benefits from forward refs; a
  dangling ref renders as a visible stub, not a silent drop or a failed write.

## SCOPE NOTE — budget-driven trims (behavior-neutral)

No behavior/param/name change beyond the added `depends_on`.
