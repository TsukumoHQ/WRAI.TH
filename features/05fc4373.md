## 2. Root cause & decisions

# liveness watchdog — kill+requeue stuck agents (task 05fc4373, niwa steal #6)

ROOT_CAUSE: A stuck agent (process gone / hung, no more relay activity) keeps its in-flight task leased, so the work never returns to the pool and the lane is silently lost — zombie agents accumulate and melt the host under load. There is a `last_seen` liveness signal and a `ReclaimTask` takeover primitive, but nothing (a) exposes "silent AND still holding work" as a queryable set for the host daemon, nor (b) releases that work back to the pool (reclaim hands it to a NEW holder; it never returns a task to pending, and neither reclaim nor ResetTask clears the lease).

## Decision (inbound-only, additive, config-gated — relay-inbound-only-no-outbound-gh)
The relay only EXPOSES candidates and provides the release primitive; the host daemon owns the graceful pane-kill (fleet-niwa-ops-1: never manual pane-kill).
- **`StuckAgents(project, threshold)` (internal/db/watchdog.go)** — read (RO pool) returning every agent whose `last_seen` idle exceeds the threshold AND that still holds an in-flight task (accepted/in-progress/in-review). Rides the existing `last_seen` + health.go classification. Excludes deactivated (graceful down) and sleeping (parked). Default threshold 30m (= health "dead" cutoff), conservative.
- **`RequeueTask(taskID, project, reason)` (internal/db/watchdog.go)** — releases a held task fully back to `pending`: assignee + lease cleared, CAS-guarded on (id, project, status) so a revived agent that finished, or a concurrent requeue, loses with TASK_STATE_CONFLICT rather than clobbering. Distinct from ReclaimTask (which assigns a new holder). Audited as a lease release (from=holder, to=(released), reason=stuck-watchdog).
- **HTTP surface** — `GET /api/agents/stuck?project=&threshold_minutes=` (the poll) + `POST /api/tasks/{id}/requeue` (the write-back). Emits `task.lease_transferred` + `task.pending` on the SSE bus.

## Rejected alternatives
- **MCP `requeue_task` tool** — built it first, then reverted: the MCP tool-schema token budget (TestToolSchemaBudget, 55296 B) was already near the ceiling and any new tool overflowed it. The watchdog is a host-daemon operation that already polls over HTTP, so HTTP-only for both read and write-back is the consistent, budget-safe choice.
- **Reuse ResetTask for requeue** — ResetTask→pending does NOT clear `lease_holder`/`lease_expires_at`, leaving a stale lease on a pooled task; the watchdog needs a clean release, hence a dedicated CAS primitive.
- **A relay-side kill loop** — violates inbound-only; the relay never reaches out. It exposes the candidate set; the daemon acts.
