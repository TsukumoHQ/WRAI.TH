# notify-rules escalation reliability (task 9990c3f9)

ROOT_CAUSE: Three independent defects in the notification engine let the fleet's SSOT go silent on escalations. (1) The "manager" target only resolved the event agent's `reports_to`; most workers have none, so ~64% of Blocked→manager firings resolved to nobody and blocked lanes went silently unescalated. (2) `buildPayload` rebuilds a fixed-field map and dropped the routing keys `dispatched_by`/`owner`, so the "dispatcher" (auto-done, 15/15 fail) and "owner" targets resolved to nobody; the MCP `emitTaskEvent` path also never carried `dispatched_by` at all. (3) After comms-discipline-s1 (DEC-relay-comms-discipline-1), every notifier message (type "notification") derives `action_required="none"` = no-wake — correct for reports, but it silences a P1 blocked escalation, and an empty-rendered template still delivered a 0-char waking message.

## Decision
- **Manager resolution** falls back to the task's dispatcher (always exists) when the assignee has no `reports_to`; `reports_to` still wins when set.
- **buildPayload carries `dispatched_by` + `owner`** so `resolveTargets` sees them with no DB round-trip; `emitTaskEvent` now carries `dispatched_by` (parity with the web-UI `taskSemantic` path). New `resolveDispatcher` helper (payload → task-record fallback).
- **Wake lever = `action_required`, not message type**: `task.blocked` force-tagged `"do"` (wakes despite type→none), `task.done` pinned `"none"` (announce, no-wake). Rules override via opts `action_required` / `no_wake`. Asserted through the real wake predicate `UnreadCountForAgent`.
- **Empty-content suppression** in `doMessage`: empty line + no structured payload → outcome `"skipped"` (not `"failed"` — `deliverEvent` no longer counts skipped toward DLQ retry).

## Rejected alternatives
- Changing the message TYPE to "fyi" to suppress wakes — wrong lever post-comms-discipline (type "notification" already derives to "none"; `action_required` is the actual wake gate).
- Editing the DB rules directly — the relay is the single writer; out-of-band writes to the live WAL DB are forbidden.

## Out of scope (data, not code) — reported to cto-tsukumo
- **auto-stale P0→P1** (BONUS): `auto-stale` is an operator rule in the **trovex-growth** project (`notification_rules` row), not code. Demoting to P1 is a config edit via the rule-update API. Interaction flag: at P1 with the default derive it would go no-wake (type→none); to stay a waking nudge it needs `"action_required":"ask"` in opts (now supported by this change).
