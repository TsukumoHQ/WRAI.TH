# Decision — b092a6be follow-up: hoist typed-ticket guard ahead of dispatchCore side-effects

ROOT_CAUSE: `dispatchCore` (internal/relay/handlers_tasks.go) auto-creates the "human"
profile and a default "Backlog" board BEFORE it calls `db.DispatchTask`. The typed-ticket
guard lives in `db.DispatchTask` (the authoritative single choke, from b092a6be), so a bare
ticket on an enforced project IS refused — but only AFTER dispatchCore has already run the
board/profile auto-create. On an enforced project with no existing board (a bare
signal-webhook or cron dispatch on niwa), the refused dispatch strands a stray empty
"Backlog" board. Flagged by review-b092a6be as a non-blocking finding on the merged change
(7f47ee8b).

## Decision
Fail fast: run the same `ProjectRequiresTypedTicket(project)` + `ticket.Missing()` predicate
at the TOP of `dispatchCore`, before any profile/board auto-create, returning the same
`*db.TypedTicketError`. `db.DispatchTask` remains the authoritative backstop (covers the
batch/api paths, which call it directly and don't auto-create boards).

No drift: one predicate (`db.TypedTicket.Missing()` + `ProjectRequiresTypedTicket`) shared by
the early fast-fail and the DB backstop — not two divergent checks.

## Rejected alternatives
- Move the board/profile auto-create to AFTER `db.DispatchTask`: rejected — DispatchTask needs
  a resolved boardID at insert time; reordering would require threading the auto-board back and
  a second write, more churn than a fast-fail guard.
- Roll back the stray board on refusal (compensating delete): rejected — refusing before the
  side-effect is simpler and leaves nothing to clean up.

## Scope
Only the dispatchCore path (dispatch_task tool, cron, signal webhook) auto-creates boards, so
only it needed the hoist. Batch/api hit `db.DispatchTask` directly (no board auto-create → no
stray board). Free-form projects unchanged. No schema change.
