## 2. Root cause & decisions

# PR-link S3 poll convergence — reconcile_pr tool

Branch: wraith/reconcile-pr-tool → main · Fast-follow to S3-relay (0997f9d) · DEC-wraith-pr-linking-1

ROOT_CAUSE: S3-relay shipped the READ half (the `relay://pr-reconcile` MCP resource + `ListPRReconcileCandidates`) but NO write-back: nothing lets the niwa poller drive an observed PR state onto the task. Today only the webhook consumer (`syncPullRequestToTask` → `ForcePRTransition`) transitions a task from PR state; `link_pr` only STORES `pr_state`, it never transitions. So a missed `pull_request` webhook could never be reconciled by the poll — the backstop had no apply step. backend-lead (S3-consumer) was blocked with no consumable convergence contract.

## Decision
Add one MCP tool `reconcile_pr(task_id, pr_state[open|merged|closed], pr_url?, pr_repo?)` — the poll twin of the webhook path:
1. records the observed state via `SetTaskPR` (COALESCE; url/repo refreshed only if passed),
2. applies the SAME one-way status-map via `ForcePRTransition` (open→in-review, merged→done, closed-unmerged→blocked),
3. returns `{task, changed}`.

Both convergence paths (webhook + poll) now share the map. Added `prTargetFromState(pr_state)` next to the existing `prTargetState(action, merged)` — the state-keyed twin — so the map lives once in intent even though it is keyed two ways.

niwa contract: read `relay://pr-reconcile` → for each candidate `gh` GET the live PR → `reconcile_pr(task_id, <live pr_state>)`. No HMAC/webhook-replay coupling.

### Rejected alternatives
- **webhook-replay** (niwa POSTs a synthetic signed `pull_request` payload to `/api/webhooks/github`): reuses all guards but couples niwa to the webhook HMAC secret. Rejected — a poll shouldn't need the inbound-webhook secret.
- **extend `link_pr` to also transition**: muddies link_pr's "store the zone opaquely" contract. A distinct tool keeps link=store, reconcile=observe+converge.

## Safety / compat
No schema, no migration — pure handler + tool + a pure helper func. Reuses `ForcePRTransition`'s existing no-resurrect (terminal stays terminal) + idempotent (already-in-target = no-op) guards. Single-writer preserved (both writes on the writer conn; poll-driven, not a hot path). Relay stays INBOUND-only: niwa reaches gh, the relay only applies what niwa observed. SetTaskPR-then-ForcePRTransition is non-atomic but self-healing (next poll re-applies; identical to the webhook path's own two-step).
