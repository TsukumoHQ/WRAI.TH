# Decision: idle-inactivated agents unreachable by dispatch (task 6509668c)

ROOT_CAUSE: An asymmetry between the direct-send path and the profile-dispatch
path, triggered by the rolling 30-min last_seen liveness sweep (NOT a calendar/date
boundary — the "date rollover" symptom is just the cutoff crossing).

- `cleanup.go:60` runs `MarkStaleAgentsInactive` every 5 min; `agents.go:188` flips
  any `status='active'` agent whose `last_seen` is >30 min old to `'inactive'`.
  `last_seen` only bumps on relay tool calls (`TouchAgent`), so a heads-down /
  idle-but-alive dev lane gets swept.
- Direct `send_message` still reaches an inactive recipient: `ResolveRecipients`
  (deliveries.go:471) has no status filter, and it uses
  `InsertMessageWithDeliveries` → a durable `'queued'` delivery row lands →
  `UnreadCountForAgent` > 0 → niwa's unread-poll wakes the lane.
- `dispatch_task` did NOT, for TWO compounding reasons:
  1. `GetAgentsByProfile` (agents.go:230) filtered `status='active'` → the swept
     worker dropped out of the fan-out entirely.
  2. Even for an active worker, the fan-out used `InsertMessage` (handlers_tasks.go:209),
     which creates NO delivery row. The inbox is delivery-based (GetInboxViaDeliveries
     JOINs deliveries), so a delivery-less message is invisible AND
     `UnreadCountForAgent` (counts queued deliveries) reads 0 → nothing to poll/wake on.
  Net: a dispatch to a swept lane produced zero wake signal; the work stranded until
  a re-register flipped the agent back to `active`.

## Decision (CTO-gated: option (a) + scoped lease-holder hardening)
1. **Durable enqueue (option a).** `GetAgentsByProfile` now selects
   `status IN ('active','sleeping','inactive')` (exclude `deleted`) — exactly
   `ListAgents`' recipient filter — so an inactive worker stays in the fan-out. AND
   the fan-out switches `InsertMessage` → `InsertMessageWithDeliveries([]string{a.Name})`
   so a durable `'queued'` delivery row lands. Together: the dispatch produces a
   pollable wake signal; niwa's existing unread-count poll wakes + re-registers the
   lane. Relay stays INBOUND-only (it exposes the queued delivery as a read; niwa
   drives the wake).
2. **Lease-holder hardening (scoped).** `MarkStaleAgentsInactive` gains a
   `NOT EXISTS` guard: don't sweep an agent that holds a task lease whose
   `lease_expires_at` is still in the future. Once the lease lapses the guard
   releases, so a truly-hung holder still loses its `active` signal and
   `reclaim_task` can take over — a dead agent never looks alive forever. Terminal
   transitions NULL the lease, so a done task's stale `lease_holder` protects nobody.

## Rejected alternatives
- **(b) idle-lane keepalive heartbeat:** band-aid; doesn't fix the direct-vs-dispatch
  asymmetry, and a crash/restart still misses the window and strands.
- **(c) is_service always-eligible opt-in:** easy to forget per-lane; `is_service`
  today only means always-eligible SENDER, and extending it to exempt the sweep would
  make a truly-dead lane look alive forever. Wrong tradeoff.
- **Change `FindActiveAgentsBySkill` too:** out of scope — separate skill-routing
  feature, not the dispatch fan-out path. Left alone per CTO.

## Scope / safety
Additive, no schema change, backward-compatible. T2 sender-eligibility untouched
(it gates the CALLER; recipient status is orthogonal — no regression). Single
guarded UPDATE for the sweep (no TOCTOU). `GetAgentsByProfile` has exactly one
caller (the dispatch fan-out), so widening it can't leak into another feature.
