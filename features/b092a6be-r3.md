# Decision — b092a6be activation: seed tsukumo typed-ticket-on (+ stale comment nit)

ROOT_CAUSE: The b092a6be guard (refuse a bare goal/AC/dod dispatch) fires only when
`ProjectRequiresTypedTicket(project)` is true, and that flag is per-project opt-in DEFAULT-OFF
(db/db.go:305-311, seeded on for niwa ONLY). So the tsukumo project — the fleet's own project,
where the 43189533 loophole was proven — was still default-off: the guard existed but never
fired for us, and 43189533-shape untyped tickets kept passing on tsukumo. Flagged as G1 in the
lifecycle audit (cto message c50f4e8e). No runtime surface (MCP tool / api / CLI) wraps
SetProjectRequiresTypedTicket, so activation is either a live-DB write or a boot seed.

## Decision
Seed `tsukumo` require_typed_ticket=1 via the SAME one-shot marker mechanism as niwa. Refactor
the niwa seed into a `seedTypedTicketOn(project, planet, marker)` closure so both rollouts share
the restart-safe logic (one-shot per settings marker; an operator opt-out via
SetProjectRequiresTypedTicket is NOT clobbered on the next restart). Activates on the relay
redeploy cto is already doing for b092a6be. Immediate alternative for cto: a live-DB
`UPDATE projects SET require_typed_ticket=1 WHERE name='tsukumo'` (offered in the reply).

Also fixes review-b092a6be-r2's nit: the webhook_signal.go comment claimed the single guard
lives in db.DispatchTask; after r2 hoisted an early guard into dispatchCore, the comment
location was stale. Updated; behavior (422 permanent refusal) unchanged.

## Rejected alternatives
- Build a runtime flip tool/api/CLI for SetProjectRequiresTypedTicket: rejected as scope creep
  tonight (fleet-down goal); the one-shot seed is deterministic and operator-owned after.
- Flip enforcement DEFAULT-ON for all projects: rejected — deliberate design; would break every
  free-form dispatcher on the many other projects the relay serves. Rollout stays per-project.
