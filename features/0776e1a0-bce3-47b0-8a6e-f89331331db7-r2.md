DECISION: (1) rewrote both new `pushStatusAsync` tests
(`internal/relay/linear_webhook_test.go`) to observe calls through a buffered
channel instead of a shared int counter — channel send/receive are
synchronized by Go's memory model, so this is race-free by construction, not
just "passes this run". No production logic changed; the primary-mirror-only
write-back gate (`linear_secondary`) itself was never wrong, only the test's
synchronization. (2) fixed the pre-existing errcheck at db.go:246
(`defer func() { _ = backupConn.Close() }()`) so trunk lint is green again —
out of scope for the fan-out feature but was in the way of reopening.

-count=1 ./...` (635 passed, zero race reports) and `golangci-lint run
--timeout=5m` v2.12.2 (0 issues, installed locally to confirm).

REJECTED ALTERNATIVE: use `sync/atomic` for the counter instead of a channel.
Rejected in favor of a channel — it also removes the sleep-poll deadline loop
entirely (replaced with a bounded `select`/`time.After`), which was itself a
minor flakiness risk under CI's slower/more contended scheduler, not just a
race.
