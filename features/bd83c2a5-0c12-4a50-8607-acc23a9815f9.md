## 2. Root cause & decisions

# comms-discipline S4 — read-only /api/metrics/comms

ROOT_CAUSE: Comms-discipline S1 (action_required tag + guard-first wake predicate) shipped
with NO way to observe its effect. The fleet had no read on whether the >=55% no-wake target
is being hit, which senders drive wakes, how fast agents actually read, or how many wakes
could be coalesced. Without a metric surface, the discipline is unfalsifiable and S1's
fleet-down regression (notifier tags) went unseen until escalations stopped waking.

## Decision
Add ONE read-only endpoint `GET /api/metrics/comms?project=&hours=` computing four views on
demand from the live tables (deliveries, messages, message_reads):
- **wake-rate / no-wake share** vs the 0.55 target, over `deliveries` under the guard-first
  wake predicate (the naive "all deliveries wake" count is the pre-discipline baseline).
- **action_required distribution per sender**, over `messages` (a send decision, not a fan-out).
- **read-latency buckets** (<1m / 1–5m / >=5m) from `message_reads.read_at - messages.created_at`.
- **coalescing candidates**: wake-eligible deliveries within 5min of a prior wake to the same
  recipient.

## Key choices / rejected alternatives
- **read_at source**: use `message_reads.read_at` (populated by mark_read), NOT the dead
  `messages.read_at` column (all-NULL). Documented in the struct.
- **Single wake predicate**: `wakePred(alias)` mirrors UnreadCountForAgent exactly, so the metric
  can NEVER silently drift from the live wake rule — the anti-pattern comms-discipline exists to kill.
- **No hot-path write / no schema change**: RO pool only, computed per-scrape. Rejected a
  materialized/aggregated table (premature; would add a writer to the hot path).
- **Window clamp**: `?hours=` default 168h (7d), clamped (0, 8760h] so a bad value can't make
  the scan unbounded or empty.

## [LEGACY_OPPORTUNITY]
The coalescing self-join is a correlated EXISTS over the window; on a very large multi-week
deliveries set an on-demand scrape could get heavy. Acceptable now (dashboard/analysis view,
not a tight-interval health probe — that's `/api/metrics`). Revisit with a covering index or a
rollup only if scrape latency is observed to bite.
