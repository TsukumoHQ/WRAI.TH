# Decision — Phase 2 referential-integrity soft integrity (task 536ecc40)

ROOT_CAUSE: After Phase 0 (detect, merged f2f48c0) + Phase 1 (reconcile-existing,
merged 09f9754c), the relay surfaces and heals the EXISTING orphans — but it
still MINTS new ones and never self-heals during uptime. DeactivateAgent /
DeleteAgent are status flips with ZERO cascade, so a deactivated agent's held +
assigned tasks dangle silently (the permanent claim-limbo source); a reassign to
a bad agent is invisible until a reboot; and orphans that appear between reboots
(an agent deactivated mid-uptime) are never re-detected because Phase 0's scan
runs only at startup.

DECISION: Ship Phase 2 (design §7, ruled) — app-layer SOFT integrity with NO
DB-level FK. Three parts:
1. Soft-cascade on deactivate/delete (CascadeAgentDeactivation, wired into
   HandleDeactivateAgent/HandleDeleteAgent): release the agent's LEASED
   non-terminal tasks -> pending immediately (CAS-guarded; handler emits
   lease_reclaimed + nudges the profile, mirroring the expired-lease sweep);
   MARK its non-leased assignments limbo (surfaced, never transitioned);
   soft-close its team + conversation memberships (left_at, never row-delete).
2. On-write soft-mark (ReassignTask, ruling Q3): reassigning to a non-resolving
   agent stamps a quarantine marker but NEVER rejects (boot-race legit).
3. Periodic GC: the referential scan rides the existing 2-minute
   StartTaskMaintenanceSweeper (the re-scan deferred from Phase 0, now that the
   markers are consumed) — re-detects uptime orphans, stamps healed refs
   resolved. Detection-only, idempotent, no new goroutine.

REJECTED ALTERNATIVE: hard-reject a write to a non-resolving ref. Rejected by
ruling Q3 — boot-race dispatch-before-register and the TSU-75 reply-path are
legitimate; the queryable marker is the value, not a refusal.

REJECTED ALTERNATIVE: on deactivate, RELEASE (not just mark) the non-leased
assigned tasks. Rejected — an assigned-but-unleased task may be intentionally
parked; nulling its assignee is a reroute the ruling forbids. Leased tasks
(actively held) are released; merely-assigned ones are marked for triage.

REJECTED ALTERNATIVE: on-write mark at message-send (the CTO's chokepoint list
named it). Reasoned skip: a sent-yet-unresolved recipient is only ever a
fleet-expected boot-race (a genuine unknown is already REFUSED by
HandleSendMessage), so marking there is a hot-path write for boot-race noise;
the periodic GC covers message recipient orphans without the hot-path cost.
Flagged for CTO override.

SCOPING NOTE: bulk stale-sweep deactivations (MarkStaleAgentsInactive in the
cleanup loop) do NOT run the handler cascade — they're covered by the existing
lease sweep (release on expiry) + the new periodic referential scan (limbo
marking). The full cascade fires on the explicit deactivate/delete tools.

LANE NOTE: the lease-release-to-pending (CascadeAgentDeactivation) and the
ReassignTask on-write mark touch the lease/task-lifecycle surface, which is
wraith-engine's FEATURE zone. Done under explicit cto-tsukumo authorization (the
Phase 2 GO message named "release held leases to pending") while wraith-engine
is down — CAS-guarded exactly like the existing SweepExpiredLeases so it cannot
double-claim. Flagged here for wraith-engine to see on respawn.
