## 2. Root cause & decisions

# 48fb2646 — RollupTokenUsage boundary-day undercount fix (R0 follow-up)

ROOT_CAUSE: RollupTokenUsage rolled up a trailing window equal to the raw retention
(both now-14d). The single calendar day straddling the purge instant (now-14d) is
only partially present in raw — its early rows purge while later ones remain — so
each 5-min tick re-summed that day to a SHRINKING partial and the `ON CONFLICT DO
UPDATE` overwrote the day's previously-complete aggregate with the partial. Once
the day fully purged from raw the last partial froze, permanently undercounting
that day and contradicting the "never drops aggregate history" contract
(cleanup.go). The original 30d-window test masked it (its window never met the 14d
raw boundary). Found by review-de1ee790 (major, non-blocking).

## Decision
Roll up only FULLY-retained calendar days: start the rollup window at the midnight
AFTER the boundary day, so the partially-purged boundary day is skipped.

- The skipped boundary day was already captured in full on earlier ticks while it
  sat wholly inside retention (rollup runs every 5 min), so its stored aggregate is
  the correct full value.
- A fully-purged day yields no SELECT row, so `ON CONFLICT` never fires for it — the
  stored aggregate is never overwritten. Together: a faithful, non-shrinking rollup.
- `retentionDays` must match the raw-retention window (cleanup.TokenUsageRetention);
  a larger value would try to sum days already purged from raw. Documented on the
  method; cleanup passes TokenUsageRetentionDays (14).

Scope: internal/db/token_usage.go only (+ its test). No schema change, no migration,
no hot-path write. Sits on top of R0 (52be273, origin/main HEAD) which introduced
the rollup table.

## Rejected alternatives
- **Widen the rollup window beyond raw retention.** Would re-scan days already
  purged from raw → those come back as 0/partial and overwrite the stored full
  value — the same undercount in the other direction. Rejected.
- **Drop the ON CONFLICT overwrite (insert-once).** Would freeze a day at its first
  partial sum (today is incomplete when first seen). Rejected — days must be
  refreshable while fully in raw. The fix keeps the refresh but bounds it to
  fully-retained days.
