# Decision — Phase 0 referential-integrity scan (task 536ecc40)

ROOT_CAUSE: The WRAI.TH relay's identity/namespace model rests on STRING natural
keys (agent name, project name, profile slug) referenced by string across ~34
tables with NO enforced FK on those refs (only 3 declared FKs, all by id/uuid).
Rows steadily accumulate that reference an identity which no longer resolves — a
deactivated/deleted agent, an unbacked profile slug — because DeactivateAgent /
DeleteAgent do zero cascade and there is no reconcile pass. Live-DB audit
(494b63233a): ~26% of tasks have an orphaned profile_slug, 511 dispatched_by
orphans, 14 non-terminal tasks assigned to a dead agent = permanent claim-limbo,
all silent (no observability).

DECISION: Ship Phase 0 (of the founder-approved 0-2 plan, design ruled by
cto-tsukumo in trovex 7c0e0b8cc39b41ff8dff486b83695f3d): a startup pass that
DETECTS + LOGS + QUARANTINES every dangling reference into a new
integrity_quarantine SIDE-TABLE. Pure observability — no enforcement, no
reroute, no deletion; every flagged row keeps its real status and stays
claimable/visible. 13 orphan classes, one writer tx, 3-step idempotent upsert
(insert-new / reopen-regressed / mark-healed-resolved, never delete). Sentinels
{linear,cron,user} allowlisted; service agents resolve via their row and are
limbo-exempt; a live name==slug agent resolves and is never mis-flagged. Runs
only inside migrate() (pre-serving, additive, idempotent, every boot). No
foreign_keys change, zero enforced FK added (Phase 3 deferred).

Ruled design decisions applied: Q1 write-sites-are-clean reframing (ACCEPTED);
Q2 side-table (not flag columns — avoids the taskColumns/scanTask lockstep
footgun); Q3 soft-mark (queryable marker, never hard-reject); Q4 const sentinels
+ dynamic is_service; Q5 tolerate+mark structural profile_slug orphans, NEVER
rewrite (profile_slug is the profile-pool key).

REJECTED ALTERNATIVE: flag columns (integrity_flag) on tasks/agents. Rejected by
ruling Q2 — it would force taskColumns↔scanTask / agentColumns↔scanAgent to stay
in lockstep (a known wraith footgun review-wraith flags) and couples the marker
to hot-table schema. The side-table is uniform across ref types and touches no
scan list.

REJECTED ALTERNATIVE (self-review, this PR): a periodic re-scan in the 5-minute
StartCleanup loop (was in my design §5). Pulled on self-review — it puts a heavy
13-check × 3-pass full-scan WRITER transaction on a hot path, for markers
nothing yet consumes. The periodic re-scan is deferred to Phase 2, paired with
the reconcile/GC that acts on the markers and can run off the writer hot path
(design §7.3). Phase 0 = startup-only, which is exactly the AC's "startup
integrity-check pass" and runs pre-serving with zero write contention.

REJECTED ALTERNATIVE: enabling foreign_keys / adding a declared composite FK.
Hard-blocked by the ruling — the relay's runtime conns already run
_foreign_keys=ON (db.go:103), so a newly declared FK would fire immediately on
the 25% orphaned rows and break every existing user DB on upgrade. That is Phase
3, explicitly out of scope.
