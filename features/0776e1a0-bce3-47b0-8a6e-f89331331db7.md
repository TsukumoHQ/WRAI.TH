# Decision — linear_project_map fan-out (task 0776e1a0)

ROOT_CAUSE: `linear_project_map` (PR #161, main@fd937de) mapped each Linear
project to exactly one relay project (map value = a single string). The
founder needs one Linear project mirrored into TWO+ relay projects at once
(founder-blocking, dev team stalled) — the existing map couldn't express a
one-to-many route, so there was no way to fan an issue out without a second,
parallel routing path.

DECISION: extend `linear_project_map`'s value to accept either a plain string
(unchanged) or a JSON array of relay projects (fan-out). `projectsFor(iss)`
resolves the ordered target list (index 0 = primary); both the webhook
(`Ingest`) and the reconcile poll (`ReconcileCycle`) loop over it and upsert
one mirror row per target project via the existing `UpsertLinearMirror`,
which already keys on `(project, linear_issue_id)` — no schema change needed
for dedup, it was already per-project-scoped.

Write-back conflict (hard risk named in the ticket): resolved as
PRIMARY-MIRROR-ONLY, not idempotent-every-writer. A new `linear_secondary`
column (`INTEGER NOT NULL DEFAULT 0`, additive via `ensureColumns`) marks a
non-primary fan-out row; `pushStatusAsync`, the standalone `comment`
write-back, and the typed-ticket refusal comment all gate on
`!task.LinearSecondary`. DEFAULT 0 means every existing single-target mirror
(the entire current fleet) stays primary — write-back is byte-identical
pre-change.

REJECTED ALTERNATIVE: idempotent/last-writer-safe write-back (every mirror
allowed to push, last one wins). Rejected — non-deterministic under
concurrent agents in different projects finishing at different times, and
strictly more code (need a CAS/timestamp race guard) for a decision the
ticket explicitly allowed picking a simpler primary-mirror rule for.

REJECTED ALTERNATIVE: a parallel fan-out path bolted alongside the existing
`mirrorProjects()`/`projectFor()` single-target flow. Rejected per the
ticket's explicit instruction — extend the existing iteration points
(webhook.go, reconcile.go, backfill.go already iterate `mirrorProjects()`),
don't add a second one that could drift from it.
